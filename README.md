# 钢结构焊缝台账、无损检测和返修闭环平台

源提示词编号：13。覆盖构件与图纸焊缝台账、二维定位、焊工资质和检测比例预警、批量检测计划、缺陷记录、返修/复检状态、Apollo GraphQL 数据层、版本快照、签字锁定和完整追溯。

## 处置链（缺陷 → 返修 → 复检 → 检测计划）

四类对象共用同一条处置链，而不是各记各的：

- **缺陷为链上节点**：每个缺陷带 `gate`（待返修 / 返修完成 / 待复检 / 已闭合）。同一处复检合格前，缺陷不闭合，"放行下道工序"一律拦截并生成「工序拦截」待复核结论。
- **每次返修单独留痕**：`Defect.repairs[]` 保留每次返修的位置、方法、结果、返修人和时间；焊缝返修次数由链上记录汇总（`totalRepairs`），不再是可随意 +1 的数字。
- **复检结论驱动流转**：复检合格才闭合缺陷、焊缝转合格；复检不合格立即退回返修，相关检测计划剔除该焊缝、修订号 +1、状态转「待复核」。
- **焊工资质失效联动计划**：登记返修时确认资质失效，该焊工所有焊缝的关联计划立即重算退回（含已完成计划）。
- **统一待复核队列**：复检不合格、资质失效、录入冲突、工序拦截都进入同一份 `reviews`，总览 / 检测 / 地图 / 审核四个页面展示同一份结论；有待复核项时批次不可锁定。

并发与可靠性：

- **先到先得**：同一焊缝同一位置的并发缺陷录入，先提交的一笔落库，后到内容存到 `Defect.conflicts[]` 并生成「录入冲突」待复核，不覆盖在先记录。
- **请求编号 + 幂等**：缺陷 / 返修 / 复检每笔写入带 `requestId`，链上按编号去重。写入失败只在请求日志里登记「失败待恢复」与原始请求，不碰台账；点「按编号恢复」重放同一请求，返修次数、复检结论、计划条目都不会重复追加。

签字锁定：

- 锁定时对当前焊缝、计划、复核结论做深拷贝只读快照；之后处置链继续演进只产生新版本，已锁定批次始终保留原快照。

## 技术栈

Angular、PrimeNG、NgRx、Angular Router、RxJS、Apollo Angular、GraphQL、TypeScript。

## 运行

```bash
npm install
npm run dev
```

开发地址：http://localhost:62056

```bash
npm run build
```

node $(find /tmp/chain-test -name chain.spec.js)
